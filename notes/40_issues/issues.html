i260917-01Pages のビルドが push で自動的に積まれない 未

2026-09-17 に2回連続で確認した。master への通常の push だけでは GitHub Actions の run が積まれず、gh api -X POST repos/OWNER/REPO/pages/builds の手動リクエストで初めてビルドが走っている。

ローカルルール4「Pages のビルドが queued で止まることがある」とは別の事象。あちらは積まれたジョブが滞留する話で、こちらはそもそも積まれない話。

原因を特定した。 ビルド履歴を古い順に並べたところ、2026-09-16 の履歴書き換え（force push）の前後で切り替わっていた。書き換え前の 8de9462 は自動でビルドされ、書き換え後の 9899a1f ・ 87de007 はどちらも自動で積まれず、手動リクエストが必要だった。gh api repos/OWNER/REPO/hooks は空で、通常の webhook 経由ではない（legacy Pages ビルドは GitHub 内部の仕組みで動く）。

対処として、Pages のソース設定を同じ値で PUT し直し、内部連携の再同期を試みた（設定自体は変えていない）。2026-09-17 の次の push で確認したが、効果はなかった。 push 直後120秒監視しても run は積まれず、Pages の最新ビルドは push 前のコミットを指したまま。手動リクエストで初めて反映した。3回連続（9/16・9/17・今回）で自動トリガーが働いていない

利用者が GitHub 側の設定で build type を一度 Actions に変更し、master / /docs の legacy へ戻す操作を行った。2026-09-18 の次の push で確認したが、これも効果はなかった。 push 直後120秒監視しても run は積まれず、手動リクエストで初めて反映した。master 側への push は4回連続（9/16・9/17・9/17・9/18）で自動トリガーが働いていない。

利用者が Pages のソースを develop / /docs に変更した。2026-09-18 の develop push（Active Directory グループ資料の掲載）で確認したところ、今度は自動でビルドが積まれた。 push 直後に run が in_progress で現れ、手動リクエストなしで反映している。master ブランチ側にだけ何かが残っていて、develop ブランチには影響していなかった、という見立てが成り立つ。

確認後、利用者が Pages のソースを master / /docs に戻した。2026-09-20 の master push（AI PC 調査プロジェクトの掲載）で確認したところ、master 側も自動でビルドが積まれるようになっていた。 push 直後に run が in_progress で現れ、手動リクエストなしで反映している。

2026-09-20 時点でいったん「解決」としたが、2026-09-21 の master push（Bun買収記事の掲載）で再発した。 push 直後150秒監視しても run は積まれず、手動リクエストで初めて反映した。develop への切り替えは恒久対策ではなく、一時的に直っただけだったことになる。

2026-09-23 の master push（目次バッジの border-radius 修正）でも確認したところ、自動でビルドが積まれた（push 直後、約90秒の監視で in_progress を確認）。

判定方法そのものに疑いが見つかった。 9/17・9/18・9/21 の「再発」判定は、いずれも push 後120〜150秒の監視で「積まれない」と判断し、そのあと手動リクエストしていた。手動リクエストで作られた run と、自動で積まれた run は Actions の一覧では見分けがつかない。9/21 に記録した run（5d167a8）は commit から約3分後に作成されており、150秒の監視を打ち切った直後の手動リクエストで作られた可能性が高い。つまりもっと待てば自動で積まれていたかどうかを、これまでの記録では確認できていない。この監視は AI が自己ペースで秒数を数えるループで行っており、実際には指定した間隔・回数どおりに待てていなかった疑いもある。

対策として、ローカルルールに「ビルド確認は実時間の sleep で待つ」を新設した。次回以降は単発の sleep 300〜600（実時間5〜10分）で待ってから run の有無を確認する。
